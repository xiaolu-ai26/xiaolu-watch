# iPhone 今日页、身体背景和对话回收

本页说明 Phone v3 功能及其边界。iPhone 负责采集经用户启用的健康／地点背景和阅读结果，常开接收电脑负责整理；手表仍可独立录音、排队和上传，手机不是音频必经中转。运行接收端的电脑需要在线，Mac 只做开发或笔记拉取时不必常开。

## 阅读入口

首页是单一“今天”页，日期选择可切历史，右上角进入设置，没有底部 Tab。

- 覆盖条只表示这一时段有已接收录音、无清晰语音、待处理或未知，不表示压力、信息价值或生产力。未知不能解释为没录音；无清晰语音只是识别结果。
- 日概览是新增的短阅读层。自然对话卡保留标题、摘要和谨慎的声音归属提示，详情可切换摘要、口语清稿及七删一改整理稿。摘要不替代全文。
- 身体背景独立显示，不混入对话摘要段落。它是基于可用记录的估计，不能解释是哪次对话造成变化；数据不足时显示未知，不补画连续曲线。
- 页面使用系统文字样式和可访问标签，时间索引以列表提供文字状态。Dynamic Type、VoiceOver 和真实内容布局仍需在目标设备验收，不能用 typecheck 代替。

## 一次性手机连接

Phone v3 使用独立的 phone principal、256-bit bearer token 和只允许背景上传、结果读取、对话回收的 scopes。它不复用手表音频密钥，也不把健康数据塞进音频 v2 接口。所有请求使用配置的 HTTPS 同源，拒绝重定向；长期 token 只进手机独立 Keychain。

接收端先按 [Phone v3 合同](phone-v3-api.md) 配置受限私有目录和服务，再在该电脑签发一次性 phone onboarding 文件：

```bash
python receiver/phone_pair.py --config <private-config.json> --output <context_root>/phone-onboarding.json
```

文件只含 endpoint 和短期 code，有效期 10 分钟，不能提交 Git 或粘贴到公开日志。在已经合法开发配对的 Mac 上，可用 Apple `devicectl device copy to` 的 appDataContainer 将它安全交付到 Phone App 的：

```text
Library/Application Support/WatchMemory/phone-onboarding.json
```

使用当前 Xcode 的 `--help` 核对设备选择及 copy 参数，不把 CoreDevice UUID 与硬件 UDID 混用。App 先把短码和稳定 attempt ID 保存到独立 Keychain，再通过 `/v3/phone/pair/claim` 认领；长期配置成功保存后才清短码。用户不需要每天扫码或抄码。该投递路径和 Phone v3 的真机结果需按实际验收记录区分，不沿用 Watch v2 的成功证明冒称已完成。

## 健康和地点：默认关闭，分别启用

身体背景只读 HealthKit 中实际存在的心率、静息心率、HRV SDNN、睡眠、步数及运动记录，不写入样本，不创建 workout 来维持录音。首次启用可读取有限近期历史以准备比较，之后使用 observer 和 anchored 增量；SDK 27 中只探测 RMSSD 类型存在，不承诺 S9 有对应或连续采样。

- 授权流程完成不等于每一种读取均获准。空结果可能是没有记录、尚未同步或权限不可用，不能直接断言读取被拒。
- 运动背景只来自真实样本或明确的 heart-rate motion metadata。缺少步数不证明静止；睡眠阶段保留系统原值，不能把躺床或清醒当睡眠。
- 采集时间、单位、来源与上传时间分开保存。手机先持久保存待传批次，收到对应 request ID 的持久 ACK 后才推进相应增量 checkpoint。后台机会由系统决定，不能保证秒级或固定分钟更新。
- 应用关闭身体背景会停止新采集并清理该域的本机待传批次；重新开启有新的起点，不自动补关闭区间。系统读取状态不透明时，只按实际可用记录降级，不宣称已经检测到撤权。

地点使用 iPhone 的大致位置、区域变化和停留事件，不在 Watch 调用不支持的接口，不持续建立高精轨迹。使用期间授权和后台停留所需权限由系统分步处理，应用只在用户明确操作时请求。城市／街区名称由系统对粗坐标反向地理解析，可能向 Apple 地理服务发送粗坐标；失败显示地点待确认，不编造建筑或门牌。

地点开关每次切换都会更新采集 epoch 和起点。旧缓存位置和跨关闭／重开的地名回调不能入队；没有真实离开时间的事件只作为点观测，不伪造停留时长。

## 数据去向

原始健康记录及坐标只在用户设备与受控接收电脑的私有存储中处理；Windows 的敏感上下文和可恢复删除副本需放在已核验 ACL 的 NTFS 私有目录。它们不出现在 today 读取 JSON，也不直接发送 DeepSeek。

“允许派生背景用于 AI”是独立选项，默认关闭。开启后也只允许有限派生标签、粗地点、时间范围和不确定性，不放开原始心率、HRV、精确坐标或轨迹。该开关不改变已有的完整转写文字处理范围；声音匹配不确定或包含他人，不等于自动丢掉内容。

关闭采集、停止未来附加和删除历史是不同动作，关闭开关不能召回此前已发送或用户独立复制的数据。应用不会修改 Apple Health 原记录，也不覆盖个人日记和唯一主待办。模型处理可能产生文字 API 费用，继续受既有预算与重试上限约束。

## 回收一段对话

详情中的回收先取得服务端只读预览。预览绑定卡片版本、续段和来源快照，并明确原音是否共享；用户取消不提交删除。只有用户按预览确认后，手机才保存并提交稳定的删除事务，响应丢失时恢复同一 request，不创建重复删除。

- 正常回收将受管理的原音、转写、摘要和发布副本移出活动路径／进入受保护的恢复区域，并记录各阶段传播状态，不等于物理安全擦除或删除独立备份。
- 其他对话、共享健康记录和地点记录不随某一张卡片删除。
- 只有真实词级边界可证明安全切分时，才允许处理共享原音；粗 ASR 父范围、未知或重叠边界必须保留共享内容并显示未全部完成。
- 飞书、笔记或用户手改冲突会保留为待处理／可重试，不把“界面隐藏”当成全部删除。应用无法撤回文字供应商已接收的内容。
- 客户端只接受专用 retirement MAC 绑定的 `410`，验证 purpose、当前上传 attempt、密文 SHA 和原始事件身份后停止旧源重传，本机字节进入可恢复区域。裸 `410` 不能授权清原音；原 stored ACK 语义不变。见 [wire v2](wire-v2.md)。

## 构建与验收状态

XcodeGen 工程声明 Phone HealthKit 和 background-delivery entitlement，以及健康、使用期间地点和后台地点的用途说明。签名账号的实际能力以 Xcode / Apple provisioning 结果为准，不能通过去掉 entitlement 假称支持。最新检查使用 Xcode 27.1 的 iPhoneOS 27.1 和 watchOS 27 SDK；更旧 SDK 的构建尚未验收。

本轮已经完成源码独立审查、双 SDK 类型检查、原生关键策略测试，以及新 Phone 和新 Watch 的完整签名构建；实际 Phone 签名和 Apple profile 均包含 HealthKit 与后台交付。签名探针和最终安装成品是不同材料，不能把嵌入旧 Watch 的探针当升级包。

设备安装、用户原生授权、实际 HealthKit 可用样本、地点后台交付、今日页真实内容，以及删除端到端的当前结果，应以本轮完成后的交付记录为准。构建成功不是健康数据读取成功，也不证明压力算法准确率；合成数据测试不当作用户的新录音入库。
